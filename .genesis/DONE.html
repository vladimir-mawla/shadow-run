1 · The Locked Spec (what we are building)

Cognitive job: Given a proposed write, project its effect against a cloned snapshot of the state it touches, gate real execution on a rollback path already existing (or an explicit human escalation when it doesn't), execute for real, then mechanically check the observed effect against the prediction. Divergence is not just logged — it flips a per-action-type trust gate into a stricter mode. "Simulate before you act": the mechanic is shadow execution, not narration — see sim-plan.md §A.1–§A.4 for the full reasoning and the three-way choice on where a projection comes from.

Inputs: an Action (domain, type, parameters — this project's own job, never decision-engine's cost/reversibility model) and a World<TState> (a typed, versioned, hashed snapshot of exactly the state slice the action touches).  →  Outputs: a ProjectedEffect (a typed diff, never a sentence), later a Reconciliation (predicted vs. observed — the falsifiability mechanism) and, when needed, a Rollback that actually runs and is verified to restore prior state.

Autonomy level: Fully autonomous for a write whose rollback is runnable and whose action type's trust gate hasn't tripped — but a write with an unavailable rollback cannot pass through execute silently; it requires an explicit human sign-off first (§A.4). A repeatedly-wrong project() for a given action type mechanically forces that type into a stricter mode (pre-validated rollback or human sign-off) via SimulatorTrust's reset-on-success counter (§A.3) — nobody has to notice the drift and manually intervene for the gate to flip.

Failure tolerance: Fail toward the least reversible-harm outcome. A stale World version, a hash mismatch, or an unproven rollback must push toward unavailable/escalate, never toward a silent execute. There is deliberately no LLM anywhere in the projection path — lib/simulate/** (M3) is grep-tested to contain zero LLM-client and zero network imports, so "you're just asking a model to guess" is falsifiable and false by construction.  |  Trust boundary: a projection is untrusted until it has been reconciled against a real, observed effect at least once; an action type's own history of reconciliations is what the trust gate reads, never a domain's own self-report of how reliable it is.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Dependency direction inward, zero cycles (modular-architecture gate)
npm run typecheck clean AND npm test green
One verify pass by a separate agent/model (L4)
No milestone's freeze boundary touched by a later milestone (freeze-boundary gate — the independent verifier's first job on every milestone)
lib/simulate/** contains zero LLM-client, fetch, or node: imports (no-story-generator gate, from M3)
A Rollback.runnable's steps is real data, actually executed through applyDeltas against real mutated state — never a mocked closure or an untested claim (rollback-is-proven gate, from M5/M7)
Every drifted/unprojected reconciliation provably feeds SimulatorTrust's counter, and the counter provably flips a real gate at threshold (consequence gate, from M4)
No field on ProjectedEffect accepts free text where a model's prose could sit (typed-not-narrated gate, from M1)
The live demo URL runs the §B scenario (clean run + injected concurrent change) end-to-end from a click (deliverable gate — the brief requires a live demo)
A clean clone plus install plus test passes with no credentials configured (clean-clone gate)

A milestone is DONE only when every applicable box above is checked by the verifier. There is deliberately no LLM in the simulation path, so any generic "LLM schema-validation" gate from a template does not apply here and was dropped.
